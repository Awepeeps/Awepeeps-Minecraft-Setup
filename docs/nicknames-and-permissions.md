# Nicknames and permissions

EssentialsX Core is the planned source of player nicknames and moderation
commands. TAB may format the tab list, but it cannot replace Minecraft's actual
overhead player name. Above-head nickname display is deferred until a maintained
community plugin has an explicit Paper 26.3 release and its Geyser/Floodgate
rendering is verified on Bedrock clients. This does not block EssentialsX.

## EssentialsX

Prefer a stable EssentialsX Core release that supports the exact Paper build and
Java runtime. If no supported stable release exists, an official development
build may be considered only when its immutable build or commit is recorded, the
exact artifact SHA-256 is verified, and that artifact passes an isolated boot
and feature check. Never use a moving `latest` URL. The manifest row remains
inactive until its exact artifact URL and SHA-256 are verified. Merge
[`config/plugins/EssentialsX/config.yml.template`](../config/plugins/EssentialsX/config.yml.template)
into EssentialsX's generated config to enable nicknames in display names and the
player list. It also selects Bukkit permissions so LuckPerms governs EssentialsX
commands, rather than EssentialsX's fallback player-command defaults. Verify the
generated config has `use-bukkit-permissions: true` after first startup.

The owner can set or clear a player's nickname with `/nick [player] <nickname|off>`.
Keep nickname administration owner-only unless the owner deliberately chooses
to let all players use `/nick`.

EssentialsX's PlaceholderAPI expansion exposes `%essentials_nickname%` for other
plugins. It is useful for compatible chat or tab formatting. It does not change
the vanilla overhead name by itself. Install and configure the Essentials
PlaceholderAPI expansion only if another installed plugin needs it. EssentialsX
Core does not add a custom chat formatter.

EssentialsX Core also includes economy capabilities. This setup leaves them
unused and grants no economy permissions. Optional EssentialsXChat, Spawn, and
Discord add-on modules are not selected.

Keep nickname use and moderation separate. Do not add EssentialsX permissions
to the default group by default. Explicitly deny
`essentials.back.onteleport`, `essentials.teleport.cooldown.bypass.back`, and
`essentials.teleport.cooldown.bypass.tpa`; Core declares these as default-true.

If the owner chooses to let every player set a nickname, grant only
`essentials.nick` to the default group. Keep `essentials.nick.others`, nickname
format/color permissions, broad `essentials.*`, economy, home, teleport, and
warp permissions ungranted. The owner can use operator access for initial
nickname administration.

No moderator group is provisioned by default. If moderation commands are needed,
create a separate vetted group and grant only `essentials.kick`,
`essentials.mute`, `essentials.tempban`, and `essentials.unban`. Keep owner
administration in console/operator access. Do not op friends as a substitute for
narrow grants.

## FreedomChat

FreedomChat is optional. The portable config template sets `rewrite-chat: false`
so it will not rewrite outgoing signed player chat into system messages. This
means FreedomChat will not prevent reports of those messages. Other settings
keep `claim-secure-chat-enforced: false`, so clients may continue to show secure
chat warnings. Setting that option to true suppresses some warnings while
advertising that secure chat is enforced; that claim is separate from
`rewrite-chat` and the template leaves it off. Client versions and access-token
state can still affect which warning is shown. Do not present the plugin as a
chat-report protection or security control.

FreedomChat configuration is version-specific. Merge the setting into the file
generated by the exact selected plugin release; check its generated config and
console after startup. Do not overwrite the generated file or assume a future
release keeps the same keys.
